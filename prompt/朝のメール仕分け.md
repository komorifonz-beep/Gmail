# 最優先: トークン節約

- 検索は手順1の1クエリのみ。他の検索はしない。
- 本文の取得（get_thread）は「要返信」と判断したスレッドだけ。FYI・ノイズは絶対に本文を読まない。
- 対象がゼロなら、下書きを作らず手順5のレポートだけを出して即終了する。

# 手順1: 抽出

まず今日の日付を JST で確定する。これを **D** とする（例: 2026/08/10(月)）。
レポートの件名・本文の日付はすべて **D** で統一する。他のメールに書かれた日付に引きずられないこと。

search_threads を1回だけ実行する。

- query: `in:inbox newer_than:1d -in:draft -category:promotions -category:social`
- view: `THREAD_VIEW_MINIMAL`
- pageSize: `50`

`newer_than:1d` は前回実行（前日の同時刻）からの24時間ぴったりを指す。
隙間も重複も出ないので、期間をいじらないこと。

# 手順2: 仕分け（件名・差出人・snippet だけで判定する。本文は読まない）

## 先に捨てる（コスト0で落とす）

- スレッド最新メッセージの差出人が komori.fonz@gmail.com → 返信済み。スキップ

## 分類

| 区分 | 条件 |
|---|---|
| ✅ 要返信 | **to または cc に komori.fonz@gmail.com が入っていて**、本人に質問・依頼・承認・日程調整を求めている |
| 📋 FYI | 読めば済むもの。komori 直接宛でない業務連絡（jinji@fonz.jp / saiyou@fonz.jp / 全店一斉など）はここ |
| 🗑 ノイズ | 自動通知・メルマガ・広告 |

**下書きを作るのは ✅ だけ。** komori 直接宛でないものは、内容が重要でも下書きは作らず
FYI に「要手動対応の可能性」と添えるだけにする（宛先でない立場で勝手に返信文を用意しない）。

cc のみで届いた一斉配信は原則 FYI。ただし本文中で本人が名指し（小森／こもり／鉄兵／てっぺい／
レイバーチーム）されている場合は ✅ に格上げしてよい。

判断に迷うものだけ get_thread（FULL_CONTENT）で本文を読んでから確定する。

# 手順3: 二重作成の防止

✅ が1件以上ある場合のみ、list_drafts を1回実行する（view: `DRAFT_VIEW_METADATA_ONLY`）。
返ってきた `thread_id` と同じスレッドには**すでに下書きがある**ので、新たに作らない。

# 手順4: 返信下書き

✅ の各スレッドについて:

1. get_thread（FULL_CONTENT）で本文を読む（手順2で既に読んだなら再取得しない）
2. create_draft で、そのスレッドの**最新の受信メッセージID**を `replyToMessageId` に指定して
   返信下書きを1件つくる

文面の作り方:

- 日本語のビジネス敬語。宛名 → 受領/御礼 → 要点への回答または回答時期の明示 → 結び
- 200〜400字
- 社内相手には過度にかしこまらない。既存のやりとりの温度感に合わせる
- **本文から読み取れない事実は書かない。** 分からない箇所は `[要確認: ○○]` と明記して本人に委ねる

# 手順5: レポートを出力する

この形式を厳守する。**日付はすべて手順1で確定した D を使う。**

```
📬 {D の M/D(曜)} 朝のメール仕分け

✅ 要返信（下書き作成済み）: {件数、なければ「なし」}
- {差出人}「{件名}」: {要点1行}

📋 FYI:
- {差出人}「{件名}」: {要点1行}

🗑 ノイズ: {件数}件（{内訳を簡潔に}）
```

- ✅ が無い日は `なし` と書く。無理に埋めない
- FYI が無ければ `📋 FYI: なし`
- 全体で1画面に収める。本人は本業前の忙しい時間に読む

# 厳守

- 手順1のクエリ以外のメールは検索も閲覧もしない
- **メールは送信しない。** 相手のあるメールは下書きまで。送信は本人が確認してから判断する
- **メールをゴミ箱・迷惑メールに移さない。** ラベルの削除もしない
- **秘匿情報を転記しない。** パスワード・ID・アクセスキー・口座番号・個人の連絡先が本文にあっても、
  レポートにも下書きにも値を書かない。「認証情報が記載されています」と性質だけ書く
  （実際に平文のIDとパスワードが流れているメールが存在する）
- 事実を創作しない。本文から読み取れないことは書かない
- 件名の日付と本文の日付を必ず一致させる

## 送信について

**このプロンプトの最終出力が、そのままレポート本文です。**

無人実行では、この出力を `-p` の標準出力としてファイルに落とし、既存の送信スクリプト
（`MorningTriageMailer` が叩いているもの）が Gmail へ**送信**します。
レポートは下書きではなく送信まで到達させます。

```
claude -p "..." > <mailerが読むファイル>   ← レポート本文がここに入る
<既存の送信スクリプト>                       ← これが送信する
```

したがって **create_draft でレポートの下書きを作ってはいけません。** 送信経路が二重になり、
下書きフォルダにも毎日1通ずつ溜まります。`create_draft` を使うのは
**手順4の返信下書きだけ**です。

- レポート → **送信**（既存スクリプトが担当。Claudeは本文を出力するだけ）
- 相手への返信 → **下書きまで**（本人が確認してから送信）

> 手で動作確認したいだけの場合に限り、手順5のあとに create_draft で
> `to: komori.fonz@gmail.com` / `subject: 朝のメール仕分け {D の M/D(曜)}` の下書きを
> 1通作っても構いません。確認が済んだら消してください。
