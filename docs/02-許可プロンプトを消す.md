# 02. 許可プロンプトを消す（本題）

上から順に試してください。上ほど安全で、上で解決すれば下は不要です。

前提として [`01-診断.md`](01-診断.md) の **A（ツール名の接頭辞）** が確定していること。

---

## 手0: ローカルの Claude Code にやらせる ← 一番ラク

JSON を自分で編集する必要はありません。**PC上の Claude Code は自分の `settings.json` を
書き換えられます。** デスクトップアプリを開いて、次をそのまま貼ってください。

```
~/.claude/settings.json の permissions に Gmail の MCP ツールを追加して。
既存の設定は消さずにマージすること。

allow に入れる:
  search_threads / get_thread / get_message / list_labels / list_drafts /
  create_draft / update_draft / label_thread / label_message

deny に入れる（無人実行でメールを消す事故を防ぐため）:
  apply_sensitive_message_label / apply_sensitive_thread_label

ツール名の接頭辞は実際に接続されている Gmail サーバに合わせて。
mcp__Gmail__ か mcp__claude_ai_Gmail__ のどちらかを /permissions で確認して、
判別できなければ両方書いておいて。
```

[`01-診断.md`](01-診断.md) の **A（ツール名の接頭辞）** の確定も、この一言に含めてあります。
現物を見られる側に判断させるのが確実です。

書き換えが終わったら**アプリを開き直してください**（起動時に読み込まれるため）。
これで済んだ場合、下の手1・手2は不要です。

> クラウド側（Claude Code on the web）のセッションではこれはできません。
> 別マシンのコンテナで動いており、お手元の `settings.json` には届かないためです。

---

## 手1: 許可リストを設定ファイルに書く（自分で書く場合）

### やること

[`../settings/settings.example.json`](../settings/settings.example.json) の中身を
`~/.claude/settings.json` にマージします。

- macOS / Linux: `~/.claude/settings.json`
- Windows: `%USERPROFILE%\.claude\settings.json`

**すでに `settings.json` がある場合**は、丸ごと上書きせず `permissions.allow` と
`permissions.deny` の配列だけを足してください（他の設定を消さないため）。
ファイルが無ければ、サンプルをそのままコピーして構いません。

### 中身

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "mcp__Gmail__search_threads",
      "mcp__Gmail__get_thread",
      "mcp__Gmail__get_message",
      "mcp__Gmail__list_labels",
      "mcp__Gmail__list_drafts",
      "mcp__Gmail__create_draft",
      "mcp__Gmail__update_draft",
      "mcp__Gmail__label_thread",
      "mcp__Gmail__label_message"
    ],
    "deny": [
      "mcp__Gmail__apply_sensitive_message_label",
      "mcp__Gmail__apply_sensitive_thread_label"
    ]
  }
}
```

サンプルファイルには `mcp__claude_ai_Gmail__` 版も併記してあります。
**どちらの接頭辞か分からなければ両方書いたままで構いません**（存在しない方は無視されるだけ）。

### `deny` を入れてある理由

`apply_sensitive_message_label` は**メールをゴミ箱／迷惑メールに移すツール**です。
無人で動かす以上、事故で消える可能性を構造的に潰しておきます。
`deny` は `allow` より強いので、うっかり許可しても発動しません。

### 全部まとめて許可したい場合

サーバ単位で書けます。ただし上の `deny` は残してください。

```json
"allow": ["mcp__Gmail"]
```

`mcp__Gmail` は Gmail サーバの全ツールに一致します。`mcp__Gmail__*` でも同じです。
なお `mcp__*` のような**サーバ名を含まないワイルドカードは allow では無効**で、
警告が出て何も許可されません（deny では有効）。

### 確認

設定を保存して Claude Code を**開き直してから**、いつもどおり仕分けを実行します。
一度もプロンプトが出なければ完了です。

---

## 手2: `/permissions` から追加する

JSON を手で書きたくない場合。Claude Code で:

```
/permissions
```

からルールを追加できます。あるいは**許可プロンプトが出たときに
「Yes, don't ask again」を選ぶ**のでも同じ効果です（設定ファイルに書き込まれます）。

手1と結果は同じなので、やりやすい方でどうぞ。

---

## 手3: それでも毎回聞かれる場合

許可リストを正しく書いたのにプロンプトが出続けるなら、**許可ルールでは消せない種類**の
ツールに当たっています。次のどちらかです。

- 組織が `ask` に設定した claude.ai コネクタのツール
- MCP 側で `requiresUserInteraction` が指定されているツール

このどちらかだと、`--permission-mode bypassPermissions` にしても**プロンプトは出ます**
（`dontAsk` にすると逆に拒否されて動きません）。設定では回避できません。

### 対処: 送信・下書き部分を Claude の外に出す

判断は Claude にさせ、**Gmail への書き込みは素のスクリプトにやらせる**構成に変えます。
レイバー資料メールが黙って動いているのと同じ形にする、ということです。

```
[Claude] 受信メールを読んで仕分け → 結果を JSON でファイルに書き出すだけ
                                              ↓
[Pythonスクリプト] JSON を読んで Gmail API / SMTP で下書き作成＋レポート送信
```

Claude 側は読み取り系ツール（`search_threads` / `get_thread`）とファイル書き込みだけに
なるので、承認を求める箇所が消えます。書き込み系は [`01-診断.md`](01-診断.md) の **C** で
見つけたレイバー資料スクリプトの SMTP 部分をそのまま流用できます。

この構成に切り替える場合は、診断結果（特に C のスクリプトの中身）を持ってきてください。
スクリプトを書き起こします。

---

## 手4: `--dangerously-skip-permissions` ← 薦めません

全プロンプトを素通しにするフラグです。**メール操作の権限を持ったセッションを
無条件で走らせる**という意味になるので、ここでは使わないでください。
手1〜3 で解決します。

（そもそも手3のケースでは、このフラグを使ってもプロンプトは消えません。）
